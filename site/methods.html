Methods

How the database is built

What is searched, how papers are screened, where the historical collection came from, and how the keyword tags are assigned. Read this before using the database for a systematic review or a bibliometric claim; the last section says what it is and is not suitable for.

1. Sources searched, and the exact queries

Not searched: Google Scholar (no API; its terms forbid automated querying), Embase, Scopus, Web of Science and PsycINFO (subscription databases without a free API). See the limitations section.

3. Screening: what is included

Two stages. A rule-based prefilter removes, without any model call: comments, editorials, letters, news, errata and retractions (by PubMed publication type); non-English records; study protocols and trial registrations without results (publication type "Clinical Trial Protocol" or a title containing "study protocol", "trial protocol", "protocol for a", "protocol paper").

Everything else is read by a large language model (currently OpenAI gpt-5-mini at low reasoning effort; the same prompt runs on Claude Sonnet 5 when an Anthropic key is configured) from the title, abstract, journal, publication types and MeSH terms, with full text when available. The prompt encodes the definitions of Wager and Atlas (2015, Nature Reviews Neuroscience). In summary, a paper is included when placebo or nocebo phenomena are an explicit focus, in one of these forms:

  • Placebo or nocebo effect, experimentally isolated: a placebo, sham, or manipulated treatment context contrasted with a reduced or absent context (placebo versus no treatment, natural history, waitlist or treatment as usual; open versus hidden administration; balanced placebo design; conditioning versus control; verbal suggestion versus neutral instruction; high- versus low-expectation instructions; dose, price, brand or route manipulations of an otherwise identical treatment). A drug-versus-placebo comparison is not a placebo-effect design.
  • Placebo or nocebo response as the object of study: change on an inert or sham treatment (or adverse events on placebo) is what the paper is about: magnitude, time course, predictors or moderators (expectation, quality of care, suggestion, personality, prior experience, trial characteristics), neural or physiological correlates, or meta-analyses pooling placebo or sham arms.
  • Mechanisms and moderators of the above, including animal models with a cue or context contrast.
  • Reviews, meta-analyses and theory whose subject is placebo or nocebo effects or responses.
  • Placebo science more broadly (attitudes and prescribing surveys, ethics, blinding methodology, placebo manufacturing, education, history): stored as adjacent rather than core.

Excluded: efficacy or safety trials, secondary analyses and meta-analyses of treatment versus placebo whose analyses concern the active treatment, even when the abstract remarks that a placebo effect may explain improvement in both groups or measures expectations in both arms (the rule is to exclude when in doubt); papers measuring expectations, satisfaction or context without relating them to a placebo or nocebo effect or response; papers where placebo appears only as a keyword or phrase; non-scientific items; protocols.

The model returns include, exclude or uncertain with a confidence and a one-sentence rationale, shown on each paper page. A rule then assigns the scope: core when included with a study focus of placebo effect, nocebo effect, placebo response or nocebo response; adjacent when included only under "placebo science more broadly" or as a letter or editorial; exclude otherwise, and always for protocols. Uncertain decisions go to a review queue. Records with no abstract anywhere (checked in PubMed, Europe PMC, Semantic Scholar and Crossref) are decided from the title alone, included only when the placebo or nocebo focus is explicit in the title, and carry a "title only" badge.

The feed shows core papers; the database shows core and adjacent papers by default, with a toggle. The full prompt is public in the repository (pipeline/prompts/classify_v2.md, version 2.0.0, September 2026). Every stored paper records which prompt version and model judged it.

4. Keyword tags

Tags are assigned in the same model call as the screening decision, from a fixed controlled vocabulary of 170 values on 12 axes. The model may only use values from the vocabulary; each value has a one-line definition the model sees. Tags describe what the paper studied or measured, not what its introduction discusses.

5. Quality, error, and suitability for systematic reviews

This database is a discovery and monitoring tool, not a registered search. Screening and tagging are done by a language model from titles and abstracts (full text only where available), with no second reviewer, and the query set is PubMed-centred and English-only. For a systematic review or meta-analysis, use it to find candidates, seed a search strategy, or check a completed search for misses; then run and report your own reproducible search in the databases your protocol requires and screen the results yourself.

  • Model error: tags and inclusion decisions are wrong in some cases. Spot checks against the JIPS selections found the exclusions to be largely correct (letters, comments, non-English, off-topic), but a formal accuracy study against a hand-rated gold set has not yet been done; when it is, precision and recall will be reported here. Each paper page shows the model's rationale and confidence and has a link to report an error; corrections override the model.
  • Coverage: PubMed-indexed literature is well covered; journals outside PubMed and Europe PMC (much of psychology and social science, books, chapters, theses) are covered only where OpenAlex surfaces them. Embase, Scopus, Web of Science and PsycINFO are not searched.
  • Language: non-English records are excluded at the prefilter.
  • Abstract-level tagging: sample size, outcome measures and findings are as reported in the abstract; "title only" papers have tags derived from the title alone and should be verified before use.
  • Time: the current year is incomplete in every chart; PubMed adds MeSH headings weeks after a record appears, so a paper found only through MeSH can appear late.
  • Provenance: every record stores its source (which query or seed found it), the date it was added, and the prompt and model versions that judged it, so a subset can be described precisely in a methods section (for example, "papers tagged placebo effect and fMRI, found by the PubMed core query, screened by prompt 2.0.0").

6. Data and code

The database is plain JSON in the public repository (github.com/torwager/scienceofplacebo): one file per publication year under data/papers/, plus the ledger of every screened candidate. The pipeline (queries, prefilter, prompt, taxonomy, build) is in the same repository and runs as a scheduled GitHub Actions workflow; the whole history of the database is in git. Metadata, tags and summaries are CC-BY-4.0; abstracts remain the copyright of their publishers. Search results and personal lists can be exported as BibTeX, RIS, DOI lists or CSV from the database and My list pages.
